# QazTil — контракты API

**Источник правды — код в `master`.** Этот документ описывает то, что сервер
отдаёт на самом деле, а не то, как мы когда-то договаривались. Если документ
расходится с кодом — прав код, а документ надо чинить.

Так решено после того, как первая версия контракта разошлась с реализацией:
в ней было `available` вместо `current`, `xp_total` вместо `xp` и строковые
идентификаторы вместо числовых.

Сверено с `master` на 16 ноября 2026.

---

## Общее

Базовый путь: `/api/v1`. Всё, кроме регистрации и входа, требует заголовок:

```
Authorization: Bearer <token>
```

**Идентификаторы — числа** (`int64`), не строки. Это касается юнитов, уроков
и упражнений. Строковые идентификаторы есть только внутри упражнения: у
вариантов, колонок и плиток (`o1`, `l1`, `t2`) — они локальны и в базе не
хранятся.

### Ошибки

| Код | Когда |
|---|---|
| 400 | некорректные данные |
| 401 | нет токена или истёк |
| 404 | не найдено |
| 409 | конфликт состояния, в том числе `нет жизней` |

Тело ошибки — объект с одним полем: `{"error":"нужна авторизация"}`.

## Профиль и статистика

### GET /me/profile

```json
{
  "id": 1,
  "email": "aidana@example.com",
  "display_name": "Айдана",
  "created_at": "2026-11-16T10:00:00Z",
  "daily_goal": 10,
  "level": "A0",
  "motivation": "life",
  "xp": 120,
  "lives": 4,
  "max_lives": 5,
  "next_life_at": null,
  "streak": 3,
  "last_lesson_on": "2026-11-15"
}
```

Профиль отдаёт и ответы онбординга, и геймификацию одним объектом.
`next_life_at` и `last_lesson_on` могут быть `null`.

### PUT /me/profile

Все поля необязательны — присылать можно только то, что меняется.

```json
{ "display_name": "Айдана", "daily_goal": 15, "level": "A1", "motivation": "work" }
```

Ответ — тот же объект, что у `GET /me/profile`.

Это и есть сохранение онбординга: экран `/setup` шлёт сюда `level`,
`motivation` и `daily_goal`.

### GET /me/stats

```json
{
  "xp": 120,
  "lives": 4,
  "max_lives": 5,
  "next_life_at": "2026-11-16T12:30:00Z",
  "streak": 3,
  "last_lesson_on": "2026-11-15"
}
```

**Жизни восстанавливаются по таймеру.** Поле `next_life_at` — когда вернётся
следующая. Это разошлось с покер-логом, где записано «без таймера», но в коде
реализован таймер, и документ следует коду.

## Путь обучения

### GET /path

```json
{
  "units": [
    {
      "id": 1,
      "situation_id": 1,
      "title_kk": "Дәмхана",
      "title_ru": "В кафе",
      "description": "Заказ, счёт и короткие реакции за столом",
      "position": 1,
      "lesson_count": 2,
      "lessons": [
        {
          "id": 1, "unit_id": 1,
          "title_kk": "Тапсырыс", "title_ru": "Заказ",
          "description": "Как попросить меню и напиток",
          "position": 1,
          "state": "completed"
        },
        {
          "id": 2, "unit_id": 1,
          "title_kk": "Есеп", "title_ru": "Счёт",
          "description": "Как попросить счёт",
          "position": 2,
          "state": "current"
        }
      ]
    }
  ],
  "current_lesson_id": 2
}
```

**`state` принимает `completed`, `current` или `locked`** — не `available`.
Считает сервер, на клиенте выводить не надо.

Урок считается пройденным, когда на все его упражнения дан хотя бы один
ответ. Отдельной таблицы прогресса нет: состояние выводится из журнала
попыток.

## Урок и упражнения

### GET /lessons/{id}

Описание урока без упражнений.

### GET /lessons/{id}/exercises

Упражнения урока. **Правильный ответ не приходит никогда** — проверка на
сервере. Заполнены только поля того типа, которому упражнение принадлежит.

```json
[
  {
    "id": 19, "lesson_id": 7, "kind": "choice", "position": 1,
    "prompt": "Я программист",
    "options": [
      { "id": "o1", "text": "Мен бағдарламашымын" },
      { "id": "o2", "text": "Кездесу сағат үште" },
      { "id": "o3", "text": "Рақмет" }
    ]
  },
  {
    "id": 21, "lesson_id": 7, "kind": "match", "position": 3,
    "prompt": "Соедините фразу с переводом",
    "pairs_left": [
      { "id": "l1", "text": "Мен бағдарламашымын" },
      { "id": "l2", "text": "Қай бөлімде жұмыс істейсіз?" }
    ],
    "pairs_right": [
      { "id": "r1", "text": "В каком отделе вы работаете?" },
      { "id": "r2", "text": "Я программист" }
    ]
  },
  {
    "id": 22, "lesson_id": 7, "kind": "assemble", "position": 4,
    "prompt": "Соберите: «Я программист»",
    "tiles": [
      { "id": "t1", "text": "бағдарламашымын" },
      { "id": "t2", "text": "Мен" },
      { "id": "t3", "text": "жұмыс" }
    ]
  },
  {
    "id": 23, "lesson_id": 7, "kind": "translate", "position": 5,
    "prompt": "Можете помочь?"
  }
]
```

Типов четыре: `choice`, `match`, `assemble`, `translate`.

В `assemble` часть плиток — отвлекающие: в правильном ответе они не
участвуют. То же и с лишней колонкой в `match`.

Упражнения, засеянные до появления `payload`, могут прийти с полем
`legacy_options` — плоским списком строк вместо `options`. Новый контент
его не использует.

### POST /exercises/{id}/answers

Форма запроса зависит от типа. Поле `kind` необязательно и ни на что не
влияет — сервер берёт тип из самого упражнения.

```json
{ "kind": "choice",    "option_id": "o1" }
{ "kind": "match",     "pairs": [["l1","r2"], ["l2","r1"]] }
{ "kind": "assemble",  "tile_ids": ["t2","t1","t3"] }
{ "kind": "translate", "answer": "Рақмет" }
```

Ответ один для всех типов:

```json
{
  "correct": false,
  "expected": "Мен бағдарламашымын",
  "lives": 3,
  "max_lives": 5,
  "lesson_failed": false
}
```

**Поле называется `expected`, не `correct_answer`.**

`expected` приходит всегда и уже готово к показу: для сопоставления это
`«Рақмет — Спасибо, Кешіріңіз — Извините»`, для сборки — собранная фраза.

`lives` — остаток после этого ответа. Жизнь тратится только на **первой**
ошибке в упражнении: повторная ошибка в том же упражнении уже бесплатна.
XP начисляется тоже только за первый верный ответ.

`lesson_failed` — true, когда на этот ответ ушла последняя жизнь. Урок
остановлен. Следующий ответ вернёт **409 «нет жизней»**, пока жизнь не
восстановится по таймеру.

Порядок проверки по типам:

- **match** — набор связей, порядок пар не важен. Неполный набор неверен.
- **assemble** — порядок плиток и есть ответ.
- **choice** — принимает `option_id`, а для старых клиентов ещё и текст в
  поле `answer`.

## Чего пока нет

- **`POST /lessons/{id}/complete`.** Отдельного эндпоинта нет и не
  планируется: XP и стрик начисляются внутри ответа на последнее упражнение
  урока. Что урок закрыт, клиент видит по `state` в `GET /path`.
- **Флаг `onboarded`** в профиле.
- **Прогресс дневной цели** в `/me/stats`.
- **Состояние урока в `GET /lessons/{id}`** — точка продолжения, остаток
  жизней, 403 для закрытого урока.

Эти четыре пункта в работе по QAZ-2. Пока их нет, `onboarded` можно
выводить на клиенте: профиль, у которого `level`, `motivation` и
`daily_goal` равны значениям по умолчанию, скорее всего не проходил
онбординг.
