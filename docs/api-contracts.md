# QazTil — контракты API для онбординга и уроков

**Статус:** спецификация. Эндпоинтов пока нет, пишутся по задачам QAZ-2 и QAZ-10.
Опубликовано заранее, чтобы фронт можно было делать параллельно, на заглушках.

**Основано на:** решении вести путь обучения по `units → lessons → exercises`
(вариант B), модели данных из QAZ-19 и формах упражнений, которые уже описаны
в `frontend/src/entities/exercise/model/types.ts`.

Если что-то в этом документе расходится с тем, что вам нужно — пишите сразу,
пока кода нет. Менять спецификацию дешевле, чем переписывать обе стороны.

---

## Общее

Базовый путь: `/api/v1`

Все эндпоинты ниже требуют заголовок:

```
Authorization: Bearer <token>
```

Токен берётся из `POST /auth/login`, как сейчас.

### Коды ошибок

| Код | Когда | Тело |
|---|---|---|
| 400 | некорректные данные | `{"error":"некорректные данные"}` |
| 401 | нет токена или истёк | `{"error":"нужна авторизация"}` |
| 403 | урок ещё закрыт | `{"error":"урок недоступен"}` |
| 404 | не найдено | `{"error":"не найдено"}` |
| 409 | конфликт состояния | `{"error":"урок уже пройден"}` |

Форма ошибки та же, что у существующих эндпоинтов: объект с одним полем `error`.

### Идентификаторы

Идентификаторы сущностей приходят **строками**, а не числами — так уже написано
во фронтовых типах, и так безопаснее для больших чисел в JavaScript.
Внутри базы это `BIGINT`.

## Для Мади — профиль и путь обучения

### GET /api/v1/me/profile

Ответы онбординга. Нужен, чтобы понять, проходил ли ученик онбординг.

```json
{
  "start_level": "A0",
  "motivation": "life",
  "daily_goal_xp": 10,
  "timezone": "Asia/Almaty",
  "onboarded": false
}
```

`onboarded: false` — онбординг не пройден, надо вести на `/setup`.

Допустимые значения: `start_level` — `A0`, `A1`, `A2`, `B1`, `B2`;
`motivation` — `work`, `study`, `life`; `daily_goal_xp` — от 1 до 200.
Экран онбординга сейчас предлагает уровни `A0`–`A2` и цели 5, 10, 15.

### GET /api/v1/me/stats

XP, стрик и прогресс дневной цели. Для экрана профиля и верхней панели.

```json
{
  "xp_total": 120,
  "streak_current": 4,
  "streak_best": 11,
  "last_lesson_date": "2026-10-27",
  "today": {
    "date": "2026-10-28",
    "xp_earned": 5,
    "goal_xp": 10,
    "goal_met": false
  }
}
```

`today.date` — **местная дата ученика** по его `timezone`, не по UTC.
Считать «сегодня» на клиенте не нужно, сервер уже это сделал.

`last_lesson_date` равен `null`, если уроков ещё не было.

### GET /api/v1/path

Путь обучения целиком: юниты с уроками и состоянием каждого урока.

```json
{
  "units": [
    {
      "id": "1",
      "title_kk": "Дәмхана",
      "title_ru": "Кафе",
      "description": "Заказ и счёт",
      "level": "A0",
      "topic": "life",
      "position": 1,
      "lessons": [
        {
          "id": "1",
          "title_kk": "Сәлемдесу",
          "title_ru": "Приветствие",
          "position": 1,
          "state": "completed",
          "correct_answers": 5,
          "total_answers": 5
        },
        {
          "id": "2",
          "title_kk": "Тапсырыс",
          "title_ru": "Заказ",
          "position": 2,
          "state": "available",
          "resume_position": 2,
          "correct_answers": 0,
          "total_answers": 0
        },
        {
          "id": "3",
          "title_kk": "Есеп",
          "title_ru": "Счёт",
          "position": 3,
          "state": "locked",
          "correct_answers": 0,
          "total_answers": 0
        }
      ]
    }
  ]
}
```

`state` — одно из `completed`, `available`, `locked`. **Считает сервер.**
Клиенту не нужно выводить доступность из порядка уроков.

`resume_position` приходит только у урока, который начат и не завершён.
Это номер упражнения, с которого продолжать.

Юниты и уроки уже отсортированы по `position`.

## Для Ерасыла — плеер урока

### GET /api/v1/lessons/{id}

Урок и его упражнения. **Правильные ответы не приходят** — проверка на сервере.

```json
{
  "id": "2",
  "unit_id": "1",
  "title_kk": "Тапсырыс",
  "title_ru": "Заказ",
  "state": "available",
  "resume_position": 2,
  "hearts_left": 3,
  "exercises": [ /* см. раздел «Типы упражнений» */ ]
}
```

`403`, если урок ещё закрыт. `404`, если такого урока нет.

### POST /api/v1/lessons/{id}/start

Начать урок или продолжить брошенный. Тела запроса нет.

```json
{
  "resume_position": 2,
  "hearts_left": 3,
  "attempt": 2
}
```

Если урок уже пройден — начинается заново: `resume_position` обнуляется,
сердца восстанавливаются до полного запаса, `attempt` растёт на единицу.

Вызывать нужно при входе в урок: именно этот запрос создаёт или обновляет
запись прогресса на сервере.

### POST /api/v1/exercises/{id}/answers

Проверка одного ответа. Форма тела зависит от типа упражнения, см. ниже.

```json
{
  "correct": true,
  "correct_answer": "Рақмет",
  "hearts_left": 3,
  "lesson_failed": false
}
```

`correct_answer` приходит **всегда**, чтобы показать правильный вариант
после ошибки. Поля `correct` и `correct_answer` совпадают с типом
`ExerciseResult`, который уже есть во фронте.

При неверном ответе `hearts_left` уменьшается на единицу.
Когда сердца кончились, приходит `lesson_failed: true` — урок остановлен,
дальше только `start` заново.

### POST /api/v1/lessons/{id}/complete

Завершение урока. Вызывать после последнего упражнения. Тела запроса нет.

```json
{
  "xp_earned": 10,
  "xp_total": 130,
  "streak_current": 5,
  "streak_increased": true,
  "today": {
    "xp_earned": 10,
    "goal_xp": 10,
    "goal_met": true
  },
  "next_lesson_id": "3"
}
```

`streak_increased: false`, если ученик уже занимался сегодня — стрик за день
растёт один раз.

`next_lesson_id` — урок, который только что открылся, или `null`,
если юнит закончился.

`409`, если урок не начат или сердца кончились.

## Типы упражнений

**Это место, где фронт и бэкенд уже один раз разошлись.** Сейчас в бэкенде
в сиде лежат `choice` и `translate`, а во фронте описаны `match` и `assemble` —
пересечение пустое. Ниже общий список из трёх типов, как решено в TSIS 6-7:
множественный выбор, сопоставление, сборка фразы.

Формы `match` и `assemble` взяты из
`frontend/src/entities/exercise/model/types.ts` — имена полей и формы ответов
те же, добавлено только `position` (порядок упражнения внутри урока).
`choice` описан в том же стиле. Тип `ExerciseResult` расширен полями
`hearts_left` и `lesson_failed`.

Общий элемент:

```ts
type ExerciseItem = { id: string; text: string }
```

### choice — выбор одного варианта

```json
{
  "id": "12",
  "kind": "choice",
  "position": 1,
  "prompt": "Как сказать «спасибо»?",
  "options": [
    { "id": "o1", "text": "Рақмет" },
    { "id": "o2", "text": "Кешіріңіз" },
    { "id": "o3", "text": "Сәлем" },
    { "id": "o4", "text": "Сау бол" }
  ]
}
```

Ответ:

```json
{ "kind": "choice", "option_id": "o1" }
```

### match — сопоставление пар

```json
{
  "id": "13",
  "kind": "match",
  "position": 2,
  "pairs_left": [
    { "id": "l1", "text": "Рақмет" },
    { "id": "l2", "text": "Сәлем" }
  ],
  "pairs_right": [
    { "id": "r1", "text": "Привет" },
    { "id": "r2", "text": "Спасибо" }
  ]
}
```

Ответ — список пар «левый, правый»:

```json
{ "kind": "match", "pairs": [["l1", "r2"], ["l2", "r1"]] }
```

Порядок пар в ответе значения не имеет.

### assemble — собрать фразу из слов

```json
{
  "id": "14",
  "kind": "assemble",
  "position": 3,
  "prompt": "Соберите: «Я пью кофе»",
  "tiles": [
    { "id": "t1", "text": "кофе" },
    { "id": "t2", "text": "Мен" },
    { "id": "t3", "text": "ішемін" },
    { "id": "t4", "text": "шай" }
  ]
}
```

Ответ — идентификаторы плиток в том порядке, в котором ученик их поставил:

```json
{ "kind": "assemble", "tile_ids": ["t2", "t1", "t3"] }
```

Лишние плитки (`t4` здесь) — это отвлекающие варианты, в ответе их быть не должно.

## Что ещё не решено

Эти два пункта ждут ответа Шокана и могут изменить контракт.

### Восстанавливаются ли сердца по таймеру

В покер-логе (TSIS 6-7, раздел 7) записано: сердца фиксированы на урок,
таймера восстановления нет. Во фронте уже реализовано восстановление одной
жизни за 30 минут (`LIFE_REGEN_MS`, поле `nextLifeAt` в `entities/learner`).

Контракт выше написан по покер-логу: сердца живут внутри попытки и
восстанавливаются при `start`. Если решим оставить таймер, в `GET /me/stats`
добавится `hearts_left` и `hearts_refill_at`, а из ответов урока они уйдут.

Это же решает судьбу `widgets/no-lives` — показывать ли там таймер ожидания.

### Что делать с типом translate

В бэкенде в сиде есть `translate` — свободный ввод перевода. В списке из трёх
типов его нет. Предлагаю перевести существующие записи сида в `assemble`
и больше `translate` не использовать. Если нужен четвёртый тип — скажите.
